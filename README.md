# LLM Risk Estimation

Camden's portion of the COSC 469/569 term project: getting an LLM to produce an
annual dollar risk estimate for accepting a given privacy policy, repeated enough
times to report means and standard deviations, in a form directly comparable to the
team's own risk calculation.

## What's here

| Path | What it is |
|---|---|
| `METHODOLOGY.md` | The replication protocol. Read this first. |
| `prompts/PROMPTS.md` | Verbatim prompt text for the three conditions. Copy from here, don't retype. |
| `fetch_policies.py` | Run once. Downloads and date-stamps policy snapshots. |
| `data/llm_run_log.xlsx` | Where runs get logged. Stats compute themselves. |
| `analyze.py` | Optional. Exports the summary as CSV for the report. |
| `policies/` | Generated by `fetch_policies.py`. Not committed — snapshots are large. |

## Order of operations

```bash
pip install requests beautifulsoup4
python3 fetch_policies.py          # once, at the start of collection
```

Then open `data/llm_run_log.xlsx`:

1. **Profiles** — fill in the US-average income, credit and savings figures, with
   sources. These come from Jules's assumption research so there's one authority per
   number.
2. **Services** — record each snapshot's date and character count from
   `policies/manifest.csv`.
3. **Run Log** — one row per run. Dropdowns on Prompt, Service, Refused and Truncated.
4. **Summary** and **Comparison** compute as you type. Nothing to run.

## The four rules

1. **A brand-new chat for every run.** Never reuse one. Prior turns contaminate the
   next estimate and destroy independence between repeats. Easiest rule to break,
   most damaging.
2. **First response only.** Never regenerate, never nudge toward a number.
3. **A refusal is data.** Set `Refused = Y`, leave the dollar cells blank, paste what
   it said. Refusal rate per condition goes in the paper.
4. **Paste the saved snapshot.** Never let the model browse to the URL — browsing
   makes the input uncontrolled.

## Scope

Tier 1 is 60 runs: six services spanning the exposure range × two prompt conditions
× five repeats. At roughly a minute per run that's about an hour and a quarter.
Tier 2 and 3 are listed in `METHODOLOGY.md` and only happen if there's time.

Three services (Claude, Truist, Epic Systems) are excluded — the ToS;DR dataset has
no usable privacy-document claims for them, so there's nothing to compare against.

## What to report

- Mean and SD of the annual figure per service, per prompt condition
- **Coefficient of variation** — the headline number. A CV above ~0.5 means the
  model's dollar estimate isn't reproducible, which is a substantive finding about
  LLMs as a risk tool regardless of which way it comes out.
- Refusal rate per condition
- **Spearman's rho between the LLM's ranking of services and the team's ranking.**
  This is the robust comparison. Neither dollar figure has ground truth, so agreement
  in *ordering* is a claim that survives scrutiny where "our number vs their number"
  does not.
